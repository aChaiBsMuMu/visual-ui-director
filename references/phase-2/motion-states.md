# Motion and states

Define Purpose and Character; Entry, Exit, Press, Hover, Selection, Expansion, Navigation, Loading, Success, Error and Data Update according to scope. Map each to trigger, affected property, feedback/transition/expressive duration family, easing, interruption and Reduced Motion alternative.

Exact durations/easing are Proposed unless supported by video or inspected interaction evidence. Motion must explain Feedback, Hierarchy, Continuity or State Change. Prohibit unrelated decorative loops. Avoid using zero motion as an excuse to omit loading, success, error or selected feedback.

A static-only product may explicitly omit transitions with a bounded exception, but MOTION.md still explains state communication and reduced-motion behavior. Static SVG sheets show state contrasts and a motion cue diagram; they cannot prove timing, keyboard behavior or runtime interactions. Record actual runtime evidence in the representative review where required.
