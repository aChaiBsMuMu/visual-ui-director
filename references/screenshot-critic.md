# Screenshot critic

Review real rendered screenshots at named devices or viewport sizes. Compare with the Reference Contract, Visual DNA, approved system, representative screen, responsive rule, and relevant platform layer.

## Loop

Implement → Render → Critique → Score → Identify top three problems → Fix → Render again → Re-score.

At least one critique is required after the first implementation. Below 80, continue iterating. From 80–89, fix the top three issues and re-render. At 90 or above, proceed to Gate C only when the remaining evidence is complete.

## Output

Include: Screen, Target, Visual DNA Match, Score, Strengths, Problems, Top Fixes, Generic UI Risk, Platform Fit, Critical Issues, and Required Re-render.

Judge focal point, reading path, composition, whitespace and density rhythm, type contrast, color budget, imagery and icon consistency, component relationships, content fit, responsive transformation, state clarity, platform behavior, accessibility-visible defects, and memorable gesture.

Do not award points for unrendered intent. Keep before/after screenshots and score records. If a fix improves one target but harms another, report the regression and continue.
