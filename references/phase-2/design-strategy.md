# Design strategy synthesis

Write DESIGN_STRATEGY.md after analysis, synthesis and judgment, before DNA or token selection. The strategy explains why, DNA defines stable visual behavior, and the system specifies implementation.

Use the [strategy template](../../assets/templates/phase-2/design-strategy.md). Required sections: Product Visual Problem, Desired User Perception translated to visual behavior, Creative Thesis, Design Priorities, Design Tensions, Product Goal → Visual Strategy Matrix, Visual Budget, Design Non-negotiables, Design Risks, Anti-patterns.

For each important tension record a tendency and conflict resolution, not a decorative numerical score: Expressive ↔ Functional; Dense ↔ Spacious; Editorial ↔ Systematic; Playful ↔ Mature; Branded ↔ Native; Immersive ↔ Efficient; Warm ↔ Precise. Select only tensions this product actually faces. Example: navigation behavior follows native convention; color, image crop and type character express brand.

The matrix columns are Product Goal, Desired Perception, Visual Behavior, Design Decision / J-ID, Rule, Failure Signal. Every perception must cash out in visible behavior.

Budget color, accent, cards, radius, shadow, border, motion and decorative effects. State role, allowed frequency or estimated area, prohibited contexts and conflict priority. No universal percentage, spacing step, radius, font or icon library is a default. Cards require containment logic; shadows cannot be the only hierarchy cue; multiple accents must not compete in a single viewport.
