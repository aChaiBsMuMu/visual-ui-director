# Reference discovery

Use this workflow only for Stage 1 or when the user asks to replace an approved direction.

## Build visual hypotheses

Turn the brief into three directions that differ in underlying visual behavior, not just accent color. Define each direction with:

- a short concept name and one-sentence thesis
- emotional target and brand character
- composition: symmetric/asymmetric, editorial/systematic, flat/spatial, calm/kinetic
- density and whitespace behavior
- type, imagery, material, and motion tendencies
- a reason it fits the product and one likely risk
- reference types to seek and a memorable visual gesture to investigate
- what could make the direction generic

If the user's brief is already narrow, offer two directions plus a faithful interpretation instead of manufacturing variety.

## Search matrix

Build queries from `product/industry + surface/task + visual property + platform`. Use English for global sources and Chinese for Chinese sources. Prefer concrete visual properties over praise words such as “beautiful,” “premium,” or “modern.”

Useful property vocabulary:

- editorial grid, asymmetric composition, typographic, monochrome, chromatic, tactile, precise, organic
- low-light, high-key, restrained, cinematic, archival, playful, dense, spacious, modular, immersive
- mobile onboarding, watch complication, desktop command center, responsive commerce, tablet workspace

For every direction, retain reusable terms in all relevant groups:

- English and Chinese
- platform-specific and industry-specific
- visual-style and editorial
- interaction or motion

## Source routing

- Behance: full case studies, brand systems, and multi-screen context
- Pinterest and Huaban: broad mood, composition, palette, and adjacent-domain discovery
- Dribbble: component-level expression; treat isolated shots cautiously
- Awwwards: brand sites, narrative composition, and motion direction
- Mobbin and official product galleries: real mobile flows and platform conventions
- Land-book or Lapa Ninja: landing-page structure
- Apple, Google, Microsoft, and official product sites: platform patterns and production reality

Search only the sources appropriate to the task. Respect sign-in and access boundaries. If direct access fails, use public image results or provide reusable queries rather than claiming the source was inspected.

## Candidate quality filter

Keep a candidate only when it has enough visible information to support a decision. Evaluate:

- relevance to product, content, audience, and target surface
- image clarity and available page context
- feasibility with the user's stack and assets
- distinctiveness from the other candidates
- accessibility or usability liabilities
- whether its strongest effect depends on unavailable photography, illustration, 3D, or motion

Reject duplicates, tiny crops, watermark-obscured images, unrelated ranking results, structurally impossible AI concepts, and references whose identity depends on copying protected artwork.

## Reference board contract

Normally present three directions with 3–5 candidates each and no more than 12 total. Each candidate needs:

- stable ID such as `A1`
- thumbnail or visible preview when the tool supports it
- creator/project title when available
- source and direct link
- why it is relevant
- traits worth borrowing
- constraints or risks

For each direction, summarize palette tendency, type character, composition, density, imagery, motion potential, suitable platforms, and reusable search keywords.

Ask the user to choose one primary reference and at most two secondary references. Require each secondary reference to contribute a named trait such as “palette only” or “navigation density only.”

After selection, create a Reference Contract containing Primary Reference and Contribution, Secondary References and Contributions, Selected Traits, Rejected Traits, Do Not Copy, Non-negotiables, and Platform Targets. This contract persists through implementation and screenshot review.

## Copyright boundary

Reference discovery is for analysis and direction. Do not extract logos, illustrations, photos, icons, or other protected assets for production. Do not promise pixel-identical copying. Preserve source links in the design decision record.
