# iPhone and iPad adaptation

Use current Apple platform conventions and repository deployment targets as constraints; verify unstable numeric platform guidance from official sources when it matters.

- Respect safe areas, system bars, Dynamic Type, VoiceOver order, Reduce Motion, Increase Contrast, and orientation requirements.
- Map navigation to the app hierarchy: tabs for top-level destinations where appropriate, navigation stacks for depth, sheets for contained tasks, and sidebars/split views on larger iPad layouts.
- Treat iPad as an adaptive workspace, not a stretched phone. Define compact/regular behavior, multitasking widths, keyboard, pointer, hover where supported, and drag/drop when relevant.
- Use native control behavior unless a custom treatment is essential to the approved visual thesis. Preserve discoverability and platform gestures.
- Express brand through semantic color, typography character, icon grammar, imagery, material, and motion while retaining system legibility and state behavior.

Test the smallest supported phone, a representative modern phone, relevant iPad widths, landscape or multitasking when supported, large Dynamic Type, dark appearance, and reduced motion.
